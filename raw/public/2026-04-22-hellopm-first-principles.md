# First principles for Product Managers: framework extract

- Source: Ankit Shukla, HelloPM
- Date: 2026-04-22
- Pasted into the project by the user on 2026-11-20
- This file keeps only short paraphrases of what the article says about each framework. The article's own text is not copied here.

- **Minimum viable product (MVP)**: A good MVP is ugly: it solves the core job badly enough to test demand; build a skateboard, not a quarter of a car.
- **Five whys**: Use it before choosing a solution: in their example, low activation traced to a paywall placed too early, not to missing onboarding videos.
- **First principles thinking**: Three habits: break systems into real parts, recombine parts across systems, question analogies. Expensive, so save it for high-stakes or stuck problems; use analogy and testing for small, reversible calls.
- **First principles thinking**: Case studies: SpaceX rocket costs, Cursor rebuilding the editor around AI, DeepSeek's training costs, Amazon's services becoming AWS.
- **build-measure-learn**: Five whys and first principles are ways to find the real problem before building the MVP.
