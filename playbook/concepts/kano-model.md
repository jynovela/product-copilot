# Kano model

## What it is

General knowledge: Noriaki Kano's model. Must-be (basic) features cause dissatisfaction when missing but no delight when present. Performance features raise satisfaction in proportion to how well they're done. Attractive features (delighters) please when present and aren't missed when absent. The original also has indifferent and reverse categories. A paired survey question (how do you feel if it's there, and if it isn't?) assigns each feature. Delighters become basics over time.

## How to use it

- Cover all basics before investing in delighters.
- Run the paired Kano questionnaire on one segment at a time.
- Re-check every year or so; categories drift.

## Watch out for

- Customers rating features they don't understand.
- Treating one survey as permanent truth.

## What the framework articles say

These are vendor and practitioner articles, not neutral sources.

- Three parts: basic features, performance features, delighters; highly quantitative and time-consuming. (see [[atlassian-6-prioritization-frameworks]])
- Two axes, how fully a need is met and how satisfied customers are; uses a with-and-without questionnaire; needs a statistically meaningful sample. (see [[tempo-9-prioritization-frameworks]])
- Rank each initiative by how likely it is to delight customers and its implementation cost; do high delight, low cost first. (see [[productplan-37-pm-frameworks]])
- Two axes: how well a need is met and resulting satisfaction; prioritize delight relative to cost. (see [[neal-cabage-21-pm-frameworks]])
- Separates basic expectations, performance enhancers and delighters based on user feedback. (see [[2026-11-20-juan-pm-frameworks-list]])
- Plot delight against implementation effort; three categories: basic, performance and excitement features; performance features have a 1:1 relationship between team effort and satisfaction. (see [[2025-07-04-contentsquare-prioritization-frameworks]])

## Contradictions

- Most sources give three categories (see [[atlassian-6-prioritization-frameworks]], [[2026-11-20-juan-pm-frameworks-list]]). General knowledge: Kano's original model also has indifferent and reverse features, and the reverse category matters, because some users actively dislike some features.
- ProductPlan and Contentsquare plot Kano as delight against implementation cost or effort, and Contentsquare says performance features scale 1:1 with team effort (see [[productplan-37-pm-frameworks]], [[2025-07-04-contentsquare-prioritization-frameworks]]). Tempo and Neal Cabage use the original axes: how fully a need is met against satisfaction (see [[tempo-9-prioritization-frameworks]], [[neal-cabage-21-pm-frameworks]]). In Kano's model the horizontal axis is how well the need is fulfilled, not effort; effort is a separate input when you prioritize.
